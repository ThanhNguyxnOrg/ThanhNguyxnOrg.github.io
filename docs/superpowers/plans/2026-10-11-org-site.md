# Org Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the ThanhNguyxnOrg static org site exactly per spec and deploy it to GitHub Pages.

**Architecture:** Astro 7 static output with React 19 islands for the three interactive pieces only; everything else pre-rendered. Numbers come from `src/data/baked.json` written by a daily cron workflow, never from the browser.

**Tech Stack:** Astro 7.3.8, TypeScript 6.0.3 strict (`astro check` rejects TS 7), React 19.3, Tailwind CSS 4.3.3, GSAP 3.15 + ScrollTrigger, zod 4.6.5, node:test (no test framework dep).

**Spec:** `docs/superpowers/specs/2026-10-11-org-site-design.md` — the plan argues from the spec; executors read both.

## Global Constraints

- `astro build` must pass with zero errors and zero warnings treated as errors off; output is pure static `dist/`.
- TypeScript `strict: true`; `astro check` clean.
- No em-dash character anywhere user-visible. No Inter font. One accent `#A16207`. Dark locked.
- Only honest metrics from `baked.json`; never link lumeo demo, npm repository.urls, or `/practice` subpath.
- User-visible copy is 100% English.
- Reduced-motion static fallbacks for every animation. 44px touch targets. Full keyboard walkthrough.
- Commit per task (repo is git-initialized in Task 0).

## Review Focus

- GitHub API 403/rate-limit mid-workflow keeps old JSON and fails the run loudly (Task 2 tests this with a 403 fixture).
- A demo URL flipping live status keeps the old value and flags it in the commit message (Task 2).
- Filter input containing regex characters is matched literally, never as pattern (Task 5).
- A repo renamed on GitHub produces a sync warning for the stale collection file instead of silent drift (Task 2).
- No-JS plus reduced-motion still shows the complete static page with the full archive list (Tasks 5 and 7).
